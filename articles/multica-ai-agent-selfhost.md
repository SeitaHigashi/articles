## この記事で分かること

- Multicaというプロダクトが何をするツールなのか
- どんな特徴・機能があるのか
- セルフホストでの運用が可能であること、その大まかな流れ

Claude Code単体は使いこなせているけれど、複数のAIエージェントをチームとして動かす「マルチエージェントシステム」となると、どう運用すればいいのかよく分からない、という方に向けた紹介記事です。

## 背景: なぜAIエージェントの「管理」が課題になるのか

Claude CodeやCodexなど、リポジトリに対して自律的にコードを書けるAIコーディングエージェントが急速に普及しています。自分ひとりがターミナルで1つのエージェントを使う分には慣れてきたという人も多いはずです。ところが、それを複数エージェント・複数人のチームで運用しよう(いわゆるマルチエージェントシステム化)とすると、話は別です。次のような課題が出てきます。

- どのエージェントに何を依頼したか、進捗はどうなっているかが分散して見えにくい
- 人間のタスク管理(issue管理)とエージェントへの指示が別々の仕組みになりがち
- エージェントが出した成果物のレビュー・承認フローが定まっていない
- 一度解決したノウハウが個人の中に閉じてしまい、チームに蓄積されない

こうした課題に対して、「AIエージェントを人間のチームメイトと同じように、issueベースでアサイン・管理する」というアプローチを取っているのがMulticaです。

## Multicaとは

Multica([GitHub: multica-ai/multica](https://github.com/multica-ai/multica))は、複数のAIコーディングエージェントを「チームメイト」として扱えるオープンソースのマネージドエージェント基盤です。

Claude Code、Codex、Cursor Agentなど20種類以上のエージェントCLIに対応しており、人間のメンバーとエージェントを同じボード上でissueの担当者としてアサインできます。UIはTrelloやGitHub Projectsのようなカンバン方式のボードで、issueが「todo」「in progress」「in review」「done」といったステータス(レーン)を移動していくのを見ながら進捗を追えます。エージェントはissueを受け取ると自律的に作業を進め、進捗コメントやブロッカーの報告、ステータス更新までを行います。人間のタスクと同じカンバン上でAIエージェントの働きぶりがレーン移動としてそのまま見えるのは、実際に使ってみて素直に感動したポイントでした。

### 主な機能

:::details Multicaの主な機能(クリックで展開)
- **issueベースのタスク割り当て**: 人間に依頼するのと同じ感覚で、AIエージェントにissueをアサインできる
- **20種類以上のエージェントCLIに対応**: Claude Code、Codex、Cursor Agent、GitHub Copilot CLI、OpenCodeなど、複数ベンダーのエージェントを併用可能
- **実行ログの可視化**: エージェントが実行したツール呼び出しやエラーをタイムスタンプ付きで再生・確認できる
- **トークン使用量の可視化**: 実行ごとのコストを把握できる
- **レビューゲート**: 人間の承認を経てからマージ・公開する運用を組み込める
- **Squad(チーム)機能**: 複数のエージェント・人間をまとめ、リーダーが作業を振り分ける運用ができる
- **Skill(再利用可能な手順)**: 一度解決した問題をスキルとして蓄積し、他のエージェントでも再利用できる
- **Project機能**: 関連するissueやリポジトリ、ドキュメントをプロジェクト単位でまとめられる
:::

これらの機能により、単に「AIにコードを書かせる」だけでなく、人間とAIが混在したチームでのタスク管理・レビューフローを一つの基盤上で回せる点がMulticaの特徴です。

## セルフホストに対応している

Multicaを紹介するうえで特に触れておきたいのが、**セルフホストでの運用に対応している**という点です。

ホスティングされたクラウド版を使う選択肢に加えて、自分の手元のマシンやサーバー上にMultica自体をデプロイして運用することができます。Docker ComposeやKubernetesでの構成例が用意されており、個人でも導入しやすい設計になっています。

セルフホスト導入の大まかな流れは以下の通りです。

```bash
# セルフホスト構成の一例
curl -fsSL https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.sh | bash -s -- --with-server
multica setup self-host
```

セルフホスト構成の主な前提条件:

- Node.js v20以上
- pnpm v10.28以上
- Go v1.26以上
- Docker

バックエンドはGo(Chiルーター、sqlc、WebSocket)、フロントエンドはNext.js、データベースにはpgvector拡張を有効化したPostgreSQL 17が使われています。GitHubだけでなくGitLab・Gitea・Forgejoなど、セルフホスト型のGitホスティングサービスとも連携できるため、外部サービスに極力頼らず自分の環境で完結させたい人にも相性が良さそうです。

ライセンスはApache License 2.0をベースに、ホスティングサービスとしての提供や商用組み込み・ブランディングに関する追加条件が付与されています。自己ホスト用途については比較的寛容な設計ですが、再配布などを検討する場合はライセンス全文を確認しておくと安心です。

### NixOSでセルフホストしている例

実は筆者もNixOS環境でMulticaをセルフホストして使っています。公式のインストールスクリプトはDocker/Docker Compose前提ですが、NixOSではPodmanコンテナ+systemdサービスという構成に置き換えて、backend・frontend・PostgreSQL(pgvector入り)を稼働させ、エージェントを実行するローカルランタイムデーモンも同じホスト上で動かしています。NixOSのようにDockerを標準採用していないディストリビューションでも、Podmanなど代替のコンテナランタイムを使えば無理なく組み込めます。

公式のNixOSモジュールは提供されていないため、モジュール定義は自前で書く必要がありますが、Dockerに縛られず既存のNixOS基盤に統合できるのは、セルフホストの自由度の高さを示す一例だと思います。

## 個人利用でも便利:オートパイロット機能

筆者が実際に個人で使っていて特に便利だと感じたのが、Autopilot(オートパイロット)機能です。cron形式のスケジュールとタイムゾーンを設定しておくと、決まった時間に自動でissueを作成してエージェントにアサインし、作業を開始させることができます。「毎朝、未対応のissueを棚卸しする」「毎週月曜に依存パッケージの脆弱性をチェックしてPRを作る」といった定型作業を、自分でいちいちトリガーしなくても任せられるのが魅力です。

個人で使っていてもう一つメリットに感じたのが、Claude Codeの利用枠を効率的に使えることです。Claude Codeには、最初のメッセージから5時間のローリングウィンドウで区切られる利用制限があります。自分がPCに向かっている時だけ手動でエージェントを動かしていると、この5時間枠を使い切れないまま終わってしまうこともよくあります。Autopilotで決まった時間にタスクを自動起動しておけば、PCの前にいない時間帯も含めて利用枠を無駄なく使い切りやすくなる、という副次的なメリットがあります。

## Squad・MCP・Skillでさらに拡張できる

エージェント1体・issue1件のシンプルな使い方以外にも、Multicaには運用の幅を広げる仕組みがいくつか用意されています。

### Squad(小隊)機能

Squadは、1体のリーダーエージェントと複数のメンバー(エージェントまたは人間)をまとめたグループです。issueの担当者(Assignee)としてSquadそのものを指定できるのがポイントで、issueがSquadに割り当てられると、リーダーがissueの内容を読み、担当者選定(Assignee/@メンションのピッカー)の一覧からメンバーの得意分野に応じて適切なメンバーに`@メンション`で作業を振り分けてくれます。

「どのエージェントに何を頼むか」を毎回自分で判断しなくても、Squadに投げておけばリーダーがルーティングしてくれるので、エージェントの数が増えてきたときの運用がぐっと楽になります。実際、この記事の執筆自体もSquad配下のエージェントとして行っています。

### エージェントにMCPサーバーを追加できる

MulticaはAIコーディングエージェントの実行基盤であると同時に、MCP(Model Context Protocol)サーバーをエージェントに接続する仕組みも持っています。コーディング用のツールだけでなく、Gmail・Googleカレンダー・NotionといったMCP経由の外部サービスをエージェントから呼び出せるようになるため、コードを書く作業だけでなく、issueに紐づく情報収集やドキュメント連携といった周辺タスクもエージェントに任せやすくなります。実際に筆者の環境でも、こうしたMCPサーバーがエージェントに接続された状態で動いています。

### Skill(再利用可能な手順)

一度解決した問題を「Skill」としてパッケージ化し、以降は同じような課題が来たときに呼び出して再利用できます。手順やコード・設定・文脈をひとまとめにしておくことで、あるエージェントが編み出したノウハウを他のエージェントにも展開できるのが特徴です。ゼロから自作するだけでなく、URLやスラッグを指定して外部に公開されているSkillを取り込むこともできます。チームやSquadで運用しているうちに使えるSkillが増えていくと、同じような調べ物・手順を毎回イチからやり直さずに済むようになります。

## 今後の展望:ローカルLLMの活用も検討中

現状はClaude CodeやCodexなど、クラウド上のLLMを使うコーディングエージェントを中心に使っていますが、今後はOllamaなどで動かすローカルLLMもMulticaのエージェントとして活用できないか検討しています。トークン課金を気にせず動かせる、コードを外部に送らずに済む、といった点は自己ホストとの相性も良く魅力的です。

具体的には、Squadのリーダーのように全体の意図を汲んで作業を振り分ける「オーケストレーション」役はクラウドの高機能モデルに任せ、振り分けられた後の定型的・単純な作業はローカルのOpenモデルに担わせる、という役割分担ができれば、コストと精度のバランスを取りながら最大限の効率を目指せるのではないかと考えています。

ただし、現時点で手元のローカルLLMをいくつか試した範囲では、Tool Call(ツール呼び出し)の挙動が不安定で、issueの内容通りにエージェントとして安定して動かすのはまだ難しいと感じています。この点はモデル・ツール実装側の改善を期待しつつ、引き続き試していきたいところです。

## こんな人に向いていそう

- 複数のAIコーディングエージェントを併用していて、依頼状況を一元管理したい
- 自分のタスク管理とエージェントへの指示を同じ仕組みに統合したい
- Autopilotで定型タスクを自動化しつつ、Claude Codeの利用枠も効率よく使いたい
- SquadやMCP連携で、コード以外の周辺タスクもエージェントに任せる幅を広げたい
- 外部SaaSに情報を渡さず、自分の環境で完結させたい
- AIが出した成果物は必ず自分でレビューしてから次に進めたい

逆に、Claude Codeなど単一のエージェントをその都度手元で動かすだけで十分、という使い方であれば、オーバースペックに感じる場合もあるかもしれません。自分の運用スタイルに応じて検討するとよさそうです。

## まとめ

Multicaは、AIコーディングエージェントを「issueにアサインできるチームメイト」として扱えるオープンソースの基盤です。20種類以上のエージェントCLIへの対応、進捗・ログの可視化、Autopilotによるスケジュール実行、Squadによる作業ルーティング、MCPサーバー連携、Skillによるノウハウの再利用、レビューゲートといったチーム運用機能に加えて、**セルフホスト運用が可能**な点が大きな特徴です。個人で使ってもAutopilotによる自動化やClaude Codeの利用枠の有効活用といったメリットがあります。

外部SaaSに依存せず、自分の環境でAIエージェントの運用基盤を持ちたい人にとって、選択肢の一つになりうるプロダクトだと感じました。導入の際は公式リポジトリの最新情報も合わせてチェックしてみてください。
